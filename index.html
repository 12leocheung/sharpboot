The browser console is a live VM running that same bytecode — the image is what runs on bare metal.

    arrays + memory guide tagged values · indexed heap blocks · mark/sweep GC

    Arrays are first-class values in SharpBoot bytecode. The kernel allocates a tagged block on the heap, zeroes it, and indexes it in constant time. Strings and arrays share the same non-leaking allocator: a mark/sweep collector reclaims blocks that are no longer reachable from globals, locals, the VM stack or the temporary string registers.

    syntaxbehavior
    int[] a = new int[8];Allocate eight int slots, initialized to 0.
    string[] names = new string[3];Allocate three string slots, initialized to "".
    a[i] / a[i] = valueBounds-checked indexing. Bad indexes stop with a runtime fault.
    a.LengthElement count stored in the block header. Works for int, string and bool arrays.
    void Fill(int[] values)Arrays are reference values, so helper methods receive and mutate the same block.

    Memory. The heap is at 0x8000–0xF000 (28 KB). Each block has a four-byte header, and the allocator splits and coalesces free blocks. When contiguous space runs out it marks roots and sweeps unreachable strings and arrays, then retries the allocation.

    Limits. Arrays use two bytes per element plus a count word. An oversized allocation, a negative size or an out-of-bounds index prints an array fault instead of corrupting the VM.

    No collection pauses. Collection happens only when an allocation cannot be satisfied, so a program that stays below the heap limit never pays for a sweep.

    using System;

class Program
{
    static int Sum(int[] values)
    {
        int total = 0;
        for (int i = 0; i < values.Length; i++)
        {
            total += values[i];
        }
        return total;
    }

    static void Main()
    {
        int[] scores = new int[6];
        for (int i = 0; i < scores.Length; i++)
        {
            scores[i] = (i + 1) * 10;
        }

        string[] names = new string[2];
        names[0] = "Ada";
        names[1] = "Grace";

        Console.WriteLine("total=" + Sum(scores));
        Console.WriteLine(names[0] + " + " + names[1]);
    }
}
    graphics api guide VGA mode 13h · 320 × 200 · 256 colors

    SharpBoot has a small bare-metal drawing API. It switches the VGA card into mode 13h and writes straight to the A000:0000 framebuffer — no OS, no .NET drawing library and no COSMOS. The same calls run in the browser VM, so the console above shows exactly what the floppy image draws.

    callresult
    Graphics.Init()Enter 320×200 mode 13h and clear to black. Drawing calls auto-start graphics if you skip this.
    Graphics.End()Return to 80×25 text mode and clear the text screen.
    Graphics.Rgb(r, g, b)Pack 0–255 RGB into a palette index. Uses 3 bits red, 3 green, 2 blue.
    Graphics.Width() / Height()Return 320 and 200.
    Graphics.Clear(color)Fill the whole framebuffer.
    Graphics.SetPixel(x, y, color)One pixel. Top-left origin; out-of-bounds pixels are ignored.
    Graphics.FillRect(x, y, w, h, color)Filled rectangle, clipped to the screen.
    Graphics.Rect(x, y, w, h, color)One-pixel rectangle outline.
    Graphics.Line(x1, y1, x2, y2, color)Bresenham line.
    Graphics.FillCircle(cx, cy, r, color)Filled circle using horizontal spans.
    Graphics.Circle(cx, cy, r, color)One-pixel circle outline.
    Graphics.SetPalette(index, r, g, b)Write one VGA DAC entry, 0–255 per channel. Call after Init(); the browser canvas uses the same palette.
    Graphics.Sprite(x, y, rows, w, h)Blit a string sprite. Space and . are transparent; 0–9 and A–F select palette entries 0–15.
    Graphics.Text(x, y, text, color)Draw an 8×8 bitmap-font string directly into the framebuffer. Lowercase is uppercased; unsupported glyphs become ?.

    Coordinates. x runs 0–319 left to right, y runs 0–199 top to bottom. Colors are 0–255 RGB components; Rgb quantizes them to the 3-3-2 palette.

    Text and input. While graphics mode is active, text writes are suppressed so they cannot corrupt the framebuffer. Call Graphics.End() before Console.WriteLine. Console.ReadKey().KeyChar still works for game input; ReadLine also reads input, but its echo is not visible in graphics mode.

    Drawing model. This is a direct framebuffer, not a retained scene or GPU API. Redraw what you need each frame. There is no double buffer or vsync, so large animations may tear.

    using System;

class Program
{
    static void Main()
    {
        Graphics.Init();
        Graphics.Clear(Graphics.Rgb(4, 10, 30));

        Graphics.FillRect(20, 20, 120, 60, Graphics.Rgb(20, 210, 160));
        Graphics.Rect(20, 20, 120, 60, Graphics.Rgb(255, 255, 255));
        Graphics.Line(0, 199, 319, 0, Graphics.Rgb(255, 110, 40));
        Graphics.FillCircle(235, 106, 54, Graphics.Rgb(255, 70, 120));

        for (int i = 1; i < 16; i++)
        {
            Graphics.SetPalette(i, i * 16, 210, 255 - i * 14);
        }

        string ship = "..1111.." + ".111111." + "11111111" + "11122111"
            + "11111111" + ".111111." + "..1..1.." + "..1..1..";
        Graphics.Sprite(24, 108, ship, 8, 8);
        Graphics.Text(24, 128, "SHARPBOOT SPRITE + BITMAP TEXT", 15);

        int key = Console.ReadKey().KeyChar;
        Graphics.End();
        Console.WriteLine("key=" + key);
    }
}
